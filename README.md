# Реализация
В архитектуре x86-64 при делении на ноль генерируется исключение Devide Error. Регистр `RIP` указывает на саму сбойную инструкцию `div/idiv`. Исключение транслируется в сигнал `SIGFPE` c `si_code = FPE_INTDIV` (Devide Error также генерируется при переполнении частного, отличать можно по `si_code`).

Для регистрации обработчика сигнала используется `sigaction`
``` C
int sigaction(int signum, const struct sigaction *act, struct sigaction *oldact);
- signum - номер сигнала (в данной работе SIGFPE)
- act - указатель на структуру с новым обработчиком
- oldact - указатель на структуру, куда запишут текущий обработчик до замены 
```

```
struct sigaction {

    union {
	    void (*sa_handler)(int);
	    void (*sa_sigaction) (int, siginfo_t *, void *);
    } __sigaction_handler;
    sigset_t   sa_mask;                                
    int        sa_flags;                                
    void     (*sa_restorer)(void);                      
};
```
В зависимости от `sa_flags` устанавливается обработчик `__sigaction_handler`. Если в `sa_flags` установлен `SA_SIGINFO` то используется обработчик `sa_sigaction`, иначе `sa_handler`

В моей реализации используется обработчик `sa_sigaction` для того, чтобы отличать переполнение от целояисленного деления на 0. 

Согласно [[1]](./doc/amd64-vol3-inst.pdf) инструкции x86-64 имеют переменную длину кодирования. Cостоит из нескольких опциональных полей, расположенных в порядке: Legacy-префикс, REX-префикс, опкод, ModR/M, SIB, смещение и непосредственное значение.

Для `div/idiv` характерны опкоды `F6` и `F7`. Поле ModR/M.reg для данных команд используется как расширение опкода: reg = 6 соответствует `div`, reg = 7 соответственно `idiv`. Алгоритм поиска длины инструкций `div/idiv` состоит в следующем: 
```
- i = 0
- пропуск REX-префикса, если есть (определяется по диапазону 0x40 - 0x4f) увеличивить i += 1;
- чтение опкода и сравнение с `F6` и `F7`. Если не равно хотя бы одному, возврат из обработчика  c -1, Иначе i += 1;
- чтение ModR/M
  - чтение поля reg и сравнение с 6 и 7. Если не равно, возрат из обработчика c -1;
  - i += 1;
  - чтение поля mod (биты 7–6) и поля r/m (биты 2–0)
  - если mod == 3 (второй операнд регистр) вернуть i;
  - если r/m == 4 (присутствует SIB): i += 1;
  - если mod == 0 и r/m == 5 (случай смещения относительно RIP: [RIP + disp32]): i += 4;
  - иначе если mod == 1(disp8): i += 1;
  - иначе если mod == 2(disp32): i += 4;
- вернуть i;
```

Для тестировавния обработчика были написаны тесты, изначально указанные в задании. Исходный код в [test.cpp](test.cpp).

# Вывод
Обработчик может исправить состояние программы, но не может исправить ее логику, которую компилятор уже изменил на этапе своего статического анализа.
Обработчик способен перехватывать сигналы, определить причину, эмулировать какой-либо результат. Однако компилятор в процессе своих агрессивных оптимизаций (в частности на основе предположений, что UB в программе нет) может удалить ветвление в программе. В таком случае Обработчик то может и обработает, но логика уже будет нарушена.
